# 1.21.11 の実API ―― jar から直接読んだもの

推測で書いた名前は 1.21.11 で軒並み変わっていた。ここにあるものは全て
`verifyMixinTargets`（`build.gradle`、ASM で jar を読む）が **jar の中で確認した** もの。
CI の annotation が唯一の出力経路なので、確認は「わざと失敗させて dump させる」形になる。

## 変わった名前

| 想定していたもの | 実際 |
| --- | --- |
| `Minecraft.runTick(DeltaTracker)` | **`runTick(Z)V`** |
| `LevelRenderer.getDeltaTracker()` | **`Minecraft.getDeltaTracker()`** |
| `LevelRenderer.getSmartCull()` | 存在しない |
| `LevelRenderer` のセクション再構築 | **`allChanged()V`** |
| `Options.fov` (int) | **`fov()LOptionInstance;`**（`.get()` で `Integer`） |
| `net.minecraft.resources.ResourceLocation` | **`net.minecraft.resources.Identifier`**（移動ではなく改名。旧名は jar から消えている） |
| `SoundInstance.getLocation()` | **`getIdentifier()Lnet/minecraft/resources/Identifier;`** |
| `SoundManager.play(...)V` | **`(...)Lnet/minecraft/client/sounds/SoundEngine$PlayResult;`**（void ではない） |
| `ClientboundLightUpdatePacket.getChunkX/Z()` | **`getX()/getZ()`** |
| `BlockPos.getX()I` | **`Vec3i` の継承**。`BlockPos` が宣言する `getX` は `(J)I` の packed-long static |
| `Particle.getParticleKey()` | **存在しない。型を表すアクセサが一つもない** |
| `SoundSource` 10定数 | **11定数。`UI` が追加** |

## 確認済みの注入先

| クラス | メソッド | 用途 |
| --- | --- | --- |
| `Minecraft` | `runTick(Z)V` | 毎tickのチェーン反応合算／爆発曝露合算／ブロック読み替え合算 |
| `Minecraft` | `tick()V` | tick毎の合算（フレームをまたいでも失われないように） |
| `ClientPacketListener` | `handleBlockUpdate`, `handleChunkBlocksUpdate`, `handleLightUpdatePacket` | 光のみ再構築判定 |
| `LevelRenderer` | `allChanged()V` | 全面描き直しの記録 |
| `ParticleEngine` | `add(LParticle;)V` | cross-mod 合計予算 |
| `Particle` | `tick()V` | 死んだパーティクルの予算返却 |
| `SoundManager` | `play(...)LPlayResult;` | 音の全パイプライン |

## 判断の記録

- **パーティクル予算のキーは `getClass().getName()`**。`Particle` に型アクセサが無いので
  `getParticleKey()` は使えない。クラス名の方が優れている面もある: 2つの mod が両方
  "flame" を出す場合、型IDなら同じ枠を食い合うが、クラスなら別々に数える。
- **音のキャンセルは `NOT_STARTED` を返す**。`PlayResult` の定数は
  `NOT_STARTED` / `STARTED` / `STARTED_SILENTLY` で、`NOT_STARTED` は
  「再生しなかった」時に元々返る値。呼び出し側は必ず処理する。
- **`isRelative()` を使う**（`getAttenuation() == NONE` と同じ判定）。relative な音は
  座標が 0 だが「原点にある」のではなく「位置を持たない」。これを位置として扱うと
  背面判定で UI・音楽・ナレーションが全部落ちる。
- **`SoundSource.UI` は `MASTER` と同じカテゴリ**（誰も埋められない唯一の枠）。
  UI 音を落とすのは軽量化ではなく操作が壊れること。

| 対象 | 実際 |
| --- | --- |
| `Camera.forwardVector()` | **`()Lorg/joml/Vector3fc;`**（可変クラスではなく読み取り専用インタフェース） |
| `Camera.NearPlane` | `getTopLeft/getTopRight/getBottomLeft/getBottomRight/getPointOnPlane(FF)`、フィールドは `forward/left/up` |
| `Level.entitiesForRendering()` | **`Level` には無い。`ClientLevel` にある** |
| `EntityRenderDispatcher.shouldRender` | `(Entity, Frustum, DDD)Z` ―― 推測どおり |
| `RenderSection.rebuildSectionAsync` | **`(RenderRegionCache)V`**（引数なしではない） |

**`Camera.NearPlane` が一番 useful。** 四隅がスクリーンの世界座標なので、
カメラの基底も射影スケールも、ゲームの角度規約を復元せずに読み出せる。

## 検証の仕組み自体について（重要）

このラウンドで検証側を 3 回直した。どれも**検証が嘘をつく**ケース:

1. `check` の一部だった → `compileJava` の `dependsOn` に変更。
   コンパイルが失敗する時こそ必要なのに、その時は一度も走らなかった。
2. 宣言メソッドしか読まない → **スーパークラスを辿る**。`BlockPos.getX` は `Vec3i` 由来で、
   「存在しない」と誤報していた。誤った「無い」は、無いチェックより悪い。信じられるから。
3. enum の定数は**フィールド**であってメソッドではない → フィールドも列挙。
   列挙しないと `PlayResult` は「定数ゼロの enum」と見える。
4. enum チェックは双方向に → 列挙した定数が存在するだけでなく、
   **jar 側にあって列挙に無い定数**を報告。片方向だけだと、まさにビルドを壊すケースで通ってしまう。
5. **survey は「失敗した時だけ」ではなく、要求したら必ず失敗させる。**
   レポートは失敗アノテーションに乗るので、緑の survey は何も届けずに1ラウンド消費する。
   調査は明示的な質問であるべき。

## Groovy の罠（`build.gradle` で4回赤くなった）

- 行頭 `+` は継続ではなく単項プラス → `MissingMethodException: String.positive()`
- 二重引用符内の `$` は補間 → `\$` にエスケープ
- **リスト要素間のカンマ抜け**が次の行を添字と解釈させる →
  `GroovyCastException: Cannot cast 'Window' ... to class 'int'`（行番号は前の行を指す）
- workflow の `::error::` は **4KB 前後で切れる** → 1ラウンドに調査するクラスは絞る
